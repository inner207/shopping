# 产品需求文档：Northstar Shop

## 1. 项目背景

原始需求是使用 React 制作一款面向海外消费者的商品选购 Web 应用。用户应能浏览商品、找到想买的商品并放入购物车；应用在电脑和手机上都应有良好体验，达到客户演示程度。产品形态、视觉设计和功能优先级由项目自行决定。

首版选择家居与日常用品作为示例目录，使用中文界面与美元价格。品牌名 Northstar Shop 为暂定名称。当前已有八件模拟商品和项目内 SVG 插画；没有真实商品或业务接口。

## 2. 用户与目标

### 目标用户

- 浏览型用户：想了解商店有哪些商品、类别和价格。
- 目标明确的用户：通过搜索或筛选找到特定商品。
- 手机用户：在较窄屏幕上比较商品，并管理购物车。

### 核心目标

用户无需帮助即可完成“浏览 → 定位商品 → 了解商品 → 加入购物车 → 修改数量”的流程。界面不得暗示已完成付款或订单提交。

## 3. 范围与优先级

| 优先级 | 功能 | 交付理由 |
| --- | --- | --- |
| P0 | 商品列表与详情 | 展示商品并支持选购决策 |
| P0 | 关键词搜索、分类筛选、价格排序 | 让用户快速找到商品 |
| P0 | 加入购物车、修改数量、移除商品、合计 | 打通选购主流程 |
| P0 | 手机与桌面布局、空状态、错误回退 | 保障现场演示稳定 |
| P0 | 购物车本地保存 | 刷新页面后仍能继续演示 |
| P1 | 价格区间筛选、推荐区、细节动效 | 主流程完成后提升发现体验 |
| 暂不做 | 登录、真实结账、支付、订单、实时库存、评价 | 需要服务端与业务规则 |

如果开发时间不足，先完成全部 P0，并保持 P1 功能不阻塞主流程。

## 4. 页面需求

### 4.1 商品列表 `/`

- 顶部包含品牌入口、搜索入口和购物车入口，购物车显示当前商品件数。
- 商品卡片显示插画、名称、类别、美元价格和详情入口，并提供加入购物车快捷按钮。
- 搜索匹配商品名称和简短描述，输入后更新结果。
- 分类包含“全部”和商品目录中存在的类别；排序包含“精选推荐”“价格从低到高”“价格从高到低”。搜索、筛选、排序可叠加。
- 结果区显示匹配数量。无结果时显示说明和清除条件的操作。
- 商品插画直接由项目内 SVG 组件绘制，不依赖远程图片。

### 4.2 商品详情 `/products/:id`

- 展示原创插画、名称、类别、价格、描述及必要规格。
- 数量默认为 1，只允许正整数；加入购物车后立即更新导航数量，并显示成功反馈。
- 直接打开无效商品 ID 时显示未找到页面，并提供返回商品列表的入口。

### 4.3 购物车 `/cart`

- 每行展示插画、名称、单价、数量、小计和移除操作；名称可以返回详情。
- 数量最低为 1。删除商品使用独立按钮，避免误触减号导致移除。
- 显示商品件数与商品合计。运费、税费没有规则，暂不纳入合计；界面应说明合计仅为商品金额。
- 空购物车提供返回购物的入口。刷新后保留有效商品及数量。
- 对损坏的本地数据或不存在的商品，页面应安全回退并保持可操作。

## 5. 体验与内容要求

- **语言与货币**：用户可见文案与无障碍标签统一为中文；价格按 `zh-CN` 区域格式显示为 USD（如 `US$48.00`）。
- **响应式**：375 px 手机、768 px 平板、1440 px 桌面视口均能完成主流程，无横向滚动。手机端筛选控件应易于打开与关闭。
- **可访问性**：按钮和输入框有可识别名称；键盘可完成搜索、筛选、打开详情、加购及购物车编辑；焦点状态清晰可见；插画有合适的无障碍名称；状态反馈不只依赖颜色。
- **视觉方向**：简洁的生活方式商店，突出商品插画、价格与主操作。移动端保证文字可读、触控目标易点按。
- **素材**：首版使用项目内原创 SVG 商品插画和模拟商品内容，客户演示时应说明其为示例。

## 6. 关键验收场景

1. 在商品列表搜索某商品名称，结果正确；切换分类和价格排序后，结果数量与顺序正确。
2. 清除搜索或筛选条件后，商品列表恢复；无匹配项时能从空状态回到商品列表。
3. 进入详情，选择数量并加入购物车；导航件数和购物车行数据同步更新。
4. 在购物车修改数量、移除商品；行小计与合计正确，刷新后状态保留。
5. 输入不存在的商品链接或损坏的本地购物车数据时，页面仍可使用；插画在无网络时仍可显示。
6. 在上述三个视口和仅使用键盘的情况下完成主流程；构建成功且无明显控制台错误。

## 7. 边界与待确认事项

首版购物车是浏览器本地演示数据，不与设备或账户同步。正式商品目录、价格和品牌尚需确认；目前使用项目内原创 SVG 插画。若后续要求真实购买，还需补充税费、运费、库存、支付、订单与隐私规则，再设计服务端接口。
