任务编号用于跟踪，不代表已经创建 issue 或分配负责人。

## 3. 每项任务的完成定义

### T01：项目骨架

建立项目依赖与脚本，配置三条路由和未找到页面。只有在安装、启动和生产构建实际成功后，才把命令写入 README。

### T02：商品与素材

已准备八件覆盖不同类别和价格的模拟商品，并为每件商品绘制 SVG 插画和无障碍名称。正式商品数据仍需客户确认。

### T03–T05：发现商品

完成清晰可读的卡片和详情页，再补搜索、筛选、排序。检查输入、清除条件、无结果、无效详情链接等边界状态。桌面与手机都应容易找到购物车入口。

### T06–T07：购物车

用整数美分计算金额，数量只能为正整数。同一商品重复加购时合并数量；刷新可恢复购物车。手动放入损坏的本地数据验证容错。

### T08：体验检查

继续在 375 px、768 px、1440 px 视口检查列表、详情、购物车。仅用键盘完成主流程，确认焦点可见、控件名称明确。插画不依赖网络，无需远程图片失败回退。

### T09：交付

执行真实构建，按产品需求文档中的关键验收场景逐项走通。README 应补上已验证的启动命令、部署地址或本地演示方式、完成范围与已知限制。不可把尚未实现的 P1 写成已完成功能。

## 4. P1 增强任务

P0 验收通过后，可按剩余时间选择：价格区间筛选、推荐区、微动效和更完整的商品信息。新增功能应更新产品需求和验收场景，并保持手机与键盘操作可用。
