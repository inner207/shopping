# 系统架构：Northstar Shop

## 1. 架构目标与现状

首版已经构建为使用本地商品数据的 React 单页应用，演示商品发现、详情和购物车流程。架构保持页面职责清楚、数据来源单一，并为将来接入真实接口留出边界。

**当前已有可运行的前端演示版。** 商品和插画是模拟内容，没有后端或正式部署环境。

## 2. 技术选型

| 层次 | 当前方案 | 作用 |
| --- | --- | --- |
| 构建 | Vite + TypeScript | 启动、打包与类型检查基础 |
| UI | React | 页面与组件状态管理 |
| 路由 | React Router | `/`、`/products/:id`、`/cart` 的直接访问 |
| 样式 | CSS Modules + CSS 变量 | 组件样式隔离、统一颜色和间距 |
| 商品数据 | 本地 TypeScript 文件 | 无后端演示的稳定数据来源 |
| 购物车 | React 状态 + `localStorage` | 即时交互和刷新恢复 |

实际依赖及脚本见项目根目录 `package.json`。

## 3. 页面与数据流

```text
本地商品目录 ──→ 商品列表 / 商品详情 ──→ 加入购物车
       │                                    │
       └────────→ 商品信息查找 ←─────────────┘
                            │
                            ↓
                  购物车状态（商品 ID + 数量）
                            │
                  ┌─────────┴─────────┐
                  ↓                   ↓
              购物车页面         localStorage
```

商品名称、价格、插画类型和描述只从商品目录读取。购物车只保存商品 ID 和数量，避免重复保存价格后产生不一致。搜索、筛选、排序结果从商品目录与当前条件计算，不单独持久化。

## 4. 数据模型

```ts
type Product = {
  id: string;
  name: string;
  category: string;
  priceCents: number;
  art: 'lamp' | 'throw' | 'vase' | 'glasses' | 'tray' | 'clock' | 'cushion' | 'basket';
  description: string;
  details: string[];
  featured: number;
  color: string;
};

type CartItem = {
  productId: string;
  quantity: number;
};
```

价格以整数美分存储和计算，显示时再格式化为美元，避免浮点数误差。商品 ID 必须唯一且稳定。购物车数量为 1–99 的整数；读取本地数据时检查结构、过滤无效商品并限制异常数量。插画由 `art` 字段选择项目内 SVG 绘图分支。

## 5. 模块划分

```text
src/
  app/             应用入口、路由和全局样式
  pages/           商品列表、商品详情、购物车、未找到页面
  components/      商品卡片、SVG 插画、数量控件
  data/            本地商品目录
  features/cart/   购物车状态、金额计算、持久化
  utils/           搜索、排序、货币格式化
index.html        HTML 入口与中文语言标记
```

页面负责组合和呈现；商品查询、金额计算和购物车变更放在可复用逻辑中。无需为首版引入复杂状态库或服务端架构。若后续接入接口，可把商品目录访问封装为数据获取层，尽量保持页面组件的输入不变。

## 6. 关键实现规则

### 商品查询

搜索时将查询文本与商品名称、描述做统一大小写处理，再叠加分类过滤与排序。排序时先复制数组，避免修改原始商品目录。无搜索结果时保留当前条件，并提供清除入口。

### 购物车

- 相同商品再次加购时累加数量；不同商品新增条目。
- 数量控件不允许 0、负数、非整数和非法文本。
- 商品合计通过各商品的 `priceCents × quantity` 求和；货币格式化仅发生在展示层。
- `localStorage` 读写需捕获异常。无法存储时，本次页面会话仍可继续使用购物车，并可提示刷新后可能丢失。
- 不存在的商品 ID 不参与金额计算，也不显示空白购物车行。

### 导航与页面状态

详情页根据 URL 中的 ID 查找商品。未找到时显示明确的未找到页面。购物车导航件数统一从购物车状态计算。加入购物车后的反馈应通过可见文字表达；必要时使用可访问的状态播报。

### 响应式与素材

采用手机优先样式。商品卡片、筛选栏和购物车行在窄屏重新排列，避免横向溢出。SVG 插画在应用内绘制，不依赖远程图片。尊重系统的减少动态效果设置。

## 7. 验证与扩展边界

本次已验证生产构建、手机视口的中文搜索与筛选、加购、改数量、移除、金额计算、刷新恢复及无效商品 URL。仍需覆盖损坏本地数据、宽屏视口和完整键盘主流程。后续可以用有针对性的自动化测试覆盖金额计算及购物车状态变化。

本架构不设计支付或真实订单。后续若要上线交易，必须先明确接口、认证、库存、运费税费、支付与错误处理规则。
